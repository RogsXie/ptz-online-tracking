# 连续保持任务修复 v5

v4在32轮、2588条真实交互、4666次更新后停止。最终训练分区探针0/8；全部案例中心精度达标，但反向8–13次，稳定性不合格。独立40例验证未启动。

证据：`verification/static-observation-v4-20261031/timeout-evidence-and-audit.json`。87次反向中81次发生在最后1秒。104个末尾移动输入固定图像并把倒计时改回中段时，完整冻结策略有79个改选Stay；固定动作候选时长仅改变Q输入时67个改选Stay。这是模型对倒计时的依赖证据，尚不是新策略成功证据。2588条回放逐项匹配日志，32条采样超时均被当成真正终止，前端hash与四网络冻结校验正常。

用户目标是持续保持，10秒是采样与评估窗口，不是物理任务终点。因此本次同时修复这一个任务语义：

- 状态只含当前RGB框的x、y、尺度、置信度，余下4槽为0；不含倒计时，也不含历史动作/趋势。仍只适用于静态固定FOV基础阶段。
- 环境返回 `terminated=False`、到采样窗口才 `truncated=True`。采样器照常重置，回放使用真正的terminated标记，时间截断保留最后实际RGB观测的价值引导；不会把重置后的其他场景作为next_state。
- 没有改动Q网络、参数梯度、奖励、动作时长范围、执行速度、学习率、batch、探索或质量门槛。gamma仍为每决策0.98。输入/任务语义不同，权重和回放从头初始化，旧v4检查点不能混入。

依据：[Pardo等，Time Limits in Reinforcement Learning，ICML2018](https://proceedings.mlr.press/v80/pardo18a.html)。该文区分有限任务的时间输入与连续任务的采样截断；对后者应从采样末状态继续bootstrap。这里是据此修正已核实的本地任务建模不一致，不能据论文保证本项目成功。

入口 `scripts/train_continuing_control_50mamba.py --output <新目录> --episodes 32 --headless`。Qlr0.0005，参数lr0.0001，batch128，每真实交互2次更新，256条预热，每100更新同步target。每8轮8个训练分区冻结探针，全部通过后才启动40例独立验证，仍要求38/40且每象限9/10。独立最终测试未使用。保持与v3/v4一致的训练和探针场景用于匹配开发比较，不冒充新的独立测试。

这是本轮改进周期第三个配置尝试（v3/v4/v5）。仍以32轮为上限，未过则进入设计复查，不自动追加轮数或连续更换配方无限重试。检测器/ReID冻结，GT仅离线匹配，没有专家动作覆盖，没有视频工程。通过静态窗口也不能宣称持续运动目标追踪已经完成。
